    \section{ $k$-means} \label{sec:kmeans}
    \textsc{Carlos --} 
    $k$-means refers to a clustering algorithm for data points in a vector space $\mathbb R^d$.
    Given a set of $n$ observations $X = \{x_1, \dots, x_n\} \subseteq \mathbb R^d$ the task is to
    find a partition of $X$ into a set of $m$ clusters $S = \{S_1, \dots, S_k\}$ such that the 
    (average) squared euclidean distance between points within each cluster is minimized, 
    i. e. find
    \begin{equation}\label{eq:km1}
        \arg\min_{S}\sum_{i=1}^k\frac{1}{\lvert S_i\rvert}\sum_{x,y \in S_i}\lVert x-y \rVert^2
        = \arg\min_{S}2\sum_{i=1}^k\sum_{x,y \in S_i}\lVert x-\mu_i \rVert^2
    \end{equation}
    where $\mu_i$ is the median (center) of cluster $S_i$, i. e.
    \[
        \mu_i = \frac{1}{|S_i|}\sum_{x\in S_i}x.
    \]
    Equality \eqref{eq:km1} follows from
    \begin{align*}
        \sum_{x,y \in S_i} \lVert x-y \rVert^2 &= \sum_{x,y \in S_i} \lVert (x-\mu_i) - (y-\mu_i) \rVert^2\\
        &= \sum_{x,y \in S_i} \lVert x-\mu_i \rVert^2 + \lVert y-\mu_i\rVert^2 - 2\langle x-\mu_i, y-\mu_i \rangle\\
        &= \sum_{x \in S_i}\lVert x-\mu_i \rVert^2 + \sum_{y \in S_i}\lVert y-\mu_i \rVert^2\\
        &\quad - 2\sum_{x,y\in S_i}\langle x-\mu_i, y-\mu_i \rangle
        \intertext{and}
        \sum_{x, y \in S_i} \langle x-\mu_i, y-\mu_i\rangle &= \left\langle \sum_{x \in S_i}x-\mu_i, \sum_{y \in S_i}y-\mu_i\right\rangle = \langle 0, 0\rangle\\
        &= 0.
    \end{align*}
    In general $k$-means clustering is \textit{np-hard}~\citep{kmeans_hardness} but there exist 
    a simple and quite useful iterative algorithm that monotonically decreases the cost function and therefore is
    guaranteed to converge albeit potentially slowly.\\
    It is often referred to as just "the $k$-means algorithm" or Lloyd's algorithm~\citep{Lloyd82}
    and it improves an existing clustering by reassigning each point to the cluster
    with the closest mean and then recalculating the means. 

    \subsection{$k$-means I}\label{sec:km1}
    Now in task $k$-means I we are given a set of one-dimensional points $P \subset \mathbb R$,
    set of center points $C \subset \mathbb R$ and a maximum distance $R \in \mathbb{R}_{\geq 0}$
    and want to determine for every point $x \in P$ if the distance (with respect to the 
    euclidean distance) to the closest center point is at most $R$, i. e.
    if 
    \[
        \min_{c \in C} \lvert x - c \rvert \leq R
    \]
    and output the closest center if that is the case and output \texttt{none in range} 
    otherwise.\\
    Finding the closest center is the first step in Lloyds algorithm and therefore 
    is useful for $k$-means clustering.\\
    Because in this case the points are only one-dimensional we can make use of the standard ordering
    on $\mathbb R$. If we first order the center points in ascending order of their value
    we can use binary search to find the closest center for each point.
    \begin{algorithm}[H]
    \caption{closest center in 1d}
    \begin{algorithmic}[1]
        \State Sort center points $C$ in ascending order.
        \For{each point $x \in P$}
            \State Perform binary search on sorted centers to find closest center point $c_x \in C$.
            \If{$(x-c_x)^2 > R$}
                \State \textbf{output} \texttt{none in range}
            \Else
                \State \textbf{output} $c_x$
            \EndIf
        \EndFor
    \end{algorithmic}
    \label{alg:cc1}
    \end{algorithm}
    \begin{theorem}
        Given a list of $n$ points $P \subset \mathbb R$, list of $k$ center
        points $C \subset \mathbb R$ (and a maximum distance $R \in \mathbb R_{\geq 0}$)
        finding the closest center $\arg\min_{c \in C} |x - c|$ for each point $x \in P$
        (and determining if its distance is at most $R$) can be done in $\mathcal O((k+n)\log k)$.
    \end{theorem}
    \begin{proof}
        Sorting the center points can be done in $\mathcal O(k\log k)$ using a standard 
        sorting algorithm such as \textit{Merge sort}~\citep{Knuth1998} and each binary search 
        on the center points takes $\mathcal O(\log k)$ time because the search space
        gets exactly halved in each iteration. Overall this results in a worst-case 
        runtime of $\mathcal O(k\log k + n\log k) = \mathcal O((k+n)\log k)$.
    \end{proof}

    
    \subsection{$k$-means II}
    Now we are faced with the more realistic setting where $d > 1$. Concretely 
    we are presented with an input stream of points $x_i \in \mathbb R^k$ and
    maximum distances $R_i \in \mathbb R_{\geq 0}$. Starting with an empty set of
    center points $C$ at each step we have to decide if the distance from $x_i$ to the closest
    center point is at most $R_i$ and if that is not the case, add $x_i$ to $C$.\\
    A naive approach would be to iterate over all center points in no particular order 
    for each point $x_i$ until the distance is less than $R_i$ or the end is reached. This has 
    a worst-case runtime of $i$ for the $i$-th point and if every point has to 
    be added to the center points the overall worst-case runtime is $\mathcal O(\sum_{i=1}^ni) = \mathcal O(n^2)$
    for an input stream of $n$ points in total.\\
    But this is not fast enough yet, so ideally we want to find a way to decide if the distance
    to the closest center point is at most $R_i$ in sublinear time by searching through
    them in a more clever way.
    \paragraph{Data structure}
    Building on the idea for $k$-means I we can construct a data structure for storing
    the center points that allows for something like binary search in the different dimensions.\\
    This leads to a data structure called $k-d$ trees. $k-d$ trees
    are binary trees with $k$-dimensional points at each node together with a $(k-1)$-dimensional
    hyperplane that splits the space into two half spaces. All points in the left subtree 
    then lie in one half space and all points in the right subtree in the other half space.\\
    The easiest way of selecting the hyperplanes is to select the $(i \mod k)$-th dimension as the 
    \textit{splitting dimension} at the $i$-th level of the tree and the corresponding coordinate of
    the point as the \textit{splitting value}.\\
    Inserting a new point then is exactly the same as for standard binary search trees.\\
    Deciding if a point is closer than a given distance to any center point can be done by
    traversing the tree until a point that is close enough has been found.
    Let $j$ be the \textit{splitting dimension} and $z$ the \textit{splitting value}, then
    if $x_j < z$ the left subtree is traversed first and the right subtree
    only has to be traversed after if $x_j - z \leq R$ which corresponds 
    to the hypersphere with radius $R$ centered at $x$ intersecting the
    splitting hyperplane as in Figure~\ref{fig:partDig}.

\paragraph{Analysis}
The space complexity of a $k-d$ tree with $n$ nodes is $\mathcal O(dn)$.\\
Inserting a new element into a $k-d$ tree takes $\mathcal O(h)$ time, where 
$h$ is the height of the tree as for any binary tree. It is easy to see
that in the worst-case $\mathcal O(h) = \mathcal O(n)$ but in practice its much better.\\
\begin{theorem}~\citep{Bentley75}
After inserting $n$ random points $x_1, \dots, x_n \in \mathbb R^d$
into an empty ($d$-dimensional) $k-d$ tree, the expected height
of the tree is $\mathbb E[h] \in \mathcal O(\log n)$. 
\end{theorem}
\noindent The runtime of the operation \texttt{is\_close($x, R$)} is somewhat more complex as 
it not only depends on $h$ but also on which bounding rectangles 
are intersected by the hypersphere centered at $x$ with radius $R$
and thus potentially have to be searched.\\
The problem is similiar to nearest-neighbor-search but with early
stopping and pruning and for the nearest-neighbor-search in certain
well-behaved $k-d$ trees, the following result exists.
\begin{theorem}~\citep{skrodzki2019}
    In a balanced $k-d$ tree the expected runtime of a nearest-neighbor-search
    is $\mathcal O(\log n)$.
\end{theorem}
The $k-d$ tree in the proof is constructed offline with all of points given 
by adding them in such an order that the \textit{splitting dimension} always maximizes 
the spread (biggest distance in that dimension) of the remaining points
and the \textit{splitting value} is the median of the remaining points in the
\textit{splitting dimension}. This results in a tree with logarithmic depth and
bounding rectangles which are closer to squares.
\noindent However in higher dimensions $d \gg 1$ the pruning 
becomes less effective because single dimensions contribute less to 
total distance and the runtime of nearest-neighbor-search
on randomly constructed $k-d$ trees is reported to approach linear time 
(\textit{Curse of Dimensionality}). see \cite{nn_dimcurse1}, \cite{nn_dimcurse2}\\



\section{Duckburg}\label{sec:duck}
\textsc{Carlos --}
In this task we are asked to find an algorithm that maximizes Scrooge McDucks (german: Dagobert Duck)
net winnings in the following lottery.\\
After paying 25\$ each, $n$ players choose an integer from $\{1, \dots, 1000\}$.
Then Scrooge is allowed to choose $i \leq 100$ integers. The reward
for each participant is now calculated as the minimum distance from his number to 
any of Scrooges numbers.\\
\;
So given set of numbers $P \subset \{1, \dots, 1000\}$ and an integer $k \leq 100$ our task 
is to find a set $S$ of $k$ integers that minimizes
\begin{equation}\label{eq:cluster_cost}
    \sum_{x \in P}\min_{s \in S}|x - s|.  
\end{equation}
In other words, we want to select $k$ center points such that the absolute distance to the center
of the cluster is minimized, when all points are clustered by assigning them to the closest center point.\\
This problem is known as \textit{k-center problem}. In general, just like $k$-means clustering
it is \textit{np-hard}, although there exist simple 2-approximations. But in our
case we want to find an exact solution. We note that in dimension one, $k$-center is equal 
to $k$-means and just as in $k$-means I we can again use the order in one dimension to our advantage.\\

\subsection{Dynamic programming algorithm}
We will prove the following theorem:
\begin{theorem}\label{thm:kcenter}
    Computing the minimal clustering cost \eqref{eq:cluster_cost} in 1d can be done
    in $\mathcal O (kn^2)$ and $\mathcal O (kn)$ space.
\end{theorem}
\begin{proof}
The first step is sorting the points from $P$ into ascending order $x_1, \dots, x_n$. Then selecting $k$ centers points
any cluster reduces to a contiguous interval and the optimal center point for any interval
is the median $\mu$, which can be coputed in constant time as $\lfloor\frac{x_i + x_j}{2}\rfloor$. We will refer to the sum of distances of an interval cluster 
\begin{equation}\label{eq:covercost}
    \sum_{l = i}^j|x_l - \mu_{i,j}| = (\mu_{i,j}-l)\mu_{i,j} - \sum_{l = i}^{\mu_{i,j}-i}x_l + \sum_{l = \mu_{i,j}+1}^{j}x_l - (j -\mu_{i,j})\mu_{i,j}   =: C(i,j)
\end{equation}
as the optimal clustering cost of the interval cluster $[i,j]$. Using prefix sums for $x_1, \dots, x_n$, 
i. e. computing and storing $\texttt{prefix}[k] = \sum_{l=1}^k x_l$ in advance, which takes $\mathcal O(n)$ time and space,
enables us to compute $C(i,j)$ with \eqref{eq:covercost} in constant time for any $1\leq i\leq j\leq n$.\\
Now let $dp[i,j]$ be the optimal clustering cost of of clustering $\{x_1, \dots, x_j\}$
with $i$ clusters, with the convention $dp[i,0]:=0$ for all $0 \leq i \leq n$. We can initialize $dp[1, m] = C(1, m)$ for all $1 \leq m \leq n$.
For $i > 1$ the recursive formula
\begin{equation}\label{eq:rec_optimality}
    dp[i, m] = \min_{1\leq l \leq m} dp[i-1, l-1] + C(l, m)
\end{equation}
holds. This can be seen by given the first $m$ points and $i$ centers, considering the
rightmost center $l$. $l$ lies between $x_1$ and $x_m$. For any those values of $c$
the optimal clustering cost consists of the optimal cost of covering the interval
$[1, l-1]$ with $i-1$ clusters $dp[i-1, l-1]$ and the cost of covering $[l, m]$ with $l$ 
$C(l, m)$. Thus minimizing over all possible values of $l$ yields the minimum cost.\\
With \eqref{eq:rec_optimality} the $dp$ array can be computed by iterating over $i$ and $m$ and 
selecting the minimum over all $1 \leq l \leq m$ in each iteration.\\
This results in a runtime of $\mathcal O(k n^2)$ and space complexity of $\mathcal O(kn)$.

\end{proof}

\section{Fast and Furious \textrm{I}} \label{sec:FFI}
    \textsc{Sebastian --} %\todo{remove newpage!}
    We are in an illegal street racing competition in Manhattan and receive a set $S$ of integer coordinates $S = \{c_1, \ldots, c_n \} = \{(x_1, y_1), \ldots, (x_n, y_n)\}$ that we have to visit, then return to the start $c_1$ to conclude the tour.
    While our opponent has to make due with a Nissan Skyline, we have a Lamborghini at our disposal that is at least twice as fast.
    The opponent however will use an optimal tour.
    As the cars capabilities are known, the victory depends on the length of the tour that we calculate and output as an answer to the coordinates received.

    The problem is thus: Find a 2-OPT approximation of the \textit{Traveling Salesman Problem} (TSP) using the $\operatorname{L_1}$ metric and output its length.
    In the two-dimensional coordinate space $\mathbb{Z}^{2}$, the distance between any two points $(c_i, c_j) \in S$ with coordinates $(x_i, y_i), (x_j, y_j)$, respectively, is given by 
    \begin{equation}
    \operatorname{d_1}(c_i,c_j) = \lvert x_i - x_j \rvert + \lvert y_i - y_j \rvert.
    \label{eq:d1}
    \end{equation}
    That is, it is the sum of the absolute values of the differences in both coordinates.
    As \citet{np-compl_geo} have shown that the $\operatorname{L_1 TSP}$ is NP-complete, we cannot hope to find any algorithm which runs in polynomial bounded time that finds the optimal tour.

    \subsection{Nearest Neighbor Algorithm}\label{sec:FFI_NN}
    This very simple heuristic is probably quite close to what most people would use if they were presented with such a task in the real world.
    In this greedy algorithm, a path is constructed as follows:

    \begin{algorithm}
        \caption{Nearest Neighbor}
        \begin{algorithmic}[1]
            \State Start with an arbitrary node.
            \State Find node not yet in path that minimizes the distance to the node last added. Add this node to the path.
            %\State Find node not yet in path that is closest to last added node and add this node to the path.
            \State When all nodes are added to the path, connect the node last added and the start node.
        \end{algorithmic}
        \label{alg:NN}
    \end{algorithm}

    Clearly, this gives a viable tour, but it cannot guarantee 2-OPT as \citet{rosenkrantz_heur} state in Theorem~\ref{thm:NearestNeighbor}.

    \begin{theorem}
        For a traveling salesman graph with n nodes

        $$
        \frac{\operatorname{NEARESTNEIGHBOR}}{\operatorname{OPTIMAL}} \leq \frac{1}{2} \left\lceil \log_2 (n) \right\rceil + \frac{1}{2}~.
        $$
        \label{thm:NearestNeighbor}
    \end{theorem}
    Note however that the nearest neighbor algorithm can be programmed to operate in time proportional to $n^2$, where $n$ is the number of nodes.
    
    Furthermore, randomization of the starting node, i.e.\ restarting the algorithm multiple times and picking the best run makes the task of finding an instance where this algorithm gives a tour that is larger than $2 \cdot \operatorname{OPT}$ challenging.
    This is probably exacerbated by the restriction of this exercise to integer coordinates.
    
    
    \subsection{Minimum Spanning Tree}\label{sec:FFI_MST}
    There are certainly better $\operatorname{L_1 TSP}$ heuristics that guarantee 2-OPT and deliver strong performance in empirical testing~\citep{ALLISON1984195}.
    While the following approach, the Minimum Spanning Tree (MST) Heuristic, guarantees 2-OPT, you would not expect it to perform competitively in most cases.
    %\citet{ALLISON1984195} state, that $B = 1.102 \cdot (\text{length of MST)}$ is a fairly reliable lower bound on the length of a TSP-tour.
    
    To construct the MST, we can use Prim's algorithm~\citep{prim_MST}.
    Algorithm~\ref{alg:MST} then runs in time $\mathcal{O}(n^2)$, where $n$ is the number of nodes.

    \begin{algorithm}
    \caption{Minimum Spanning Tree}
        \begin{algorithmic}[1]
            \State Given the coordinates, compute a MST.
            \State Duplicate all edges of this MST and return this length.
        \end{algorithmic}
        \label{alg:MST}
    \end{algorithm}
    
    \begin{theorem}
        Algorithm~\ref{alg:MST} gives a 2-approximation of the TSP problem.
        More precisely, the cost of all edges is $2 \cdot \operatorname{OPT}_{\operatorname{MST}} \leq 2 \cdot \operatorname{OPT}_{\operatorname{TSP}}$
        \label{thm:MST}
    \end{theorem}

    To prove this theorem, we first prove the following Lemma~\ref{lem:TSP_MST}:
    
    \begin{lemma}
        The cost of an optimal tour $\operatorname{OPT}_{\operatorname{TSP}}$ is at least as large as the weight of a minimum spanning tree $\operatorname{OPT}_{\operatorname{MST}}$.
        \label{lem:TSP_MST}
    \end{lemma}
    \begin{proof}
        Consider the optimal traveling salesman tour $\operatorname{OPT}_{\operatorname{TSP}}$.
        Delete one edge of the TSP tour.
        This gives a (non-minimal) spanning tree of cost at most $\operatorname{OPT}_{\operatorname{TSP}}$.
        %Note that this spanning tree is not necessarily minimal.
    \end{proof}

    From Lemma~\ref{lem:TSP_MST}, the proof for Theorem~\ref{thm:MST} follows immediately.
    \begin{proof}
        We note that this algorithm constructs a valid tour by duplicating all edges of the MST. The cost of this tour is then given by Lemma~\ref{lem:TSP_MST} to be at most $2 \cdot \operatorname{OPT}_{\operatorname{TSP}}$.
    \end{proof}

We are given a square grid of size $n$ with $1 \le n \le 300$, with entries $A_{i,j} \in \{-100,\ldots,100\}$.

\paragraph{Goal.}
Among all axis-aligned rectangles $R = [i_1..i_2] \times [j_1..j_2]$ with $1 \le i_1 \le i_2 \le n$ and $1 \le j_1 \le j_2 \le n$, maximize
\[
\mathrm{val}(R) \;=\; \sum_{i=i_1}^{i_2} \sum_{j=j_1}^{j_2} A_{i,j}.
\]

\subsection{Maximum Subarray in 1D (Kadane's Algorithm)}

Before solving the 2D variant efficiently, we will take a look at the 1D maximum subarray problem. For a sequence $(a_1,\ldots,a_m)$, find a contiguous subarray with maximum sum. Kadane's algorithm maintains
\[
\texttt{curEndAt}_i = \max\{a_i,\, \texttt{curEndAt}_{i-1} + a_i\}\quad\text{and}\quad
\texttt{best} = \max\{\texttt{best},\, \texttt{curEndAt}_i\}.
\]
Intuition: either the optimal subarray ending at $i$ continues the previous one (if it helps) or it restarts at $i$.

\begin{algorithm}
\caption{Kadane1D$(a_1,\ldots,a_m)$}
\begin{algorithmic}[1]
\State $\texttt{best} \gets a_1$, \ $\texttt{cur} \gets a_1$
\For{$i \gets 2$ \textbf{to} $m$}
  \State $\texttt{cur} \gets \max(a_i,\ \texttt{cur} + a_i)$
  \State $\texttt{best} \gets \max(\texttt{best},\ \texttt{cur})$
\EndFor
\State \textbf{return} $\texttt{best}$
\end{algorithmic}
\end{algorithm}

\paragraph{Correctness (sketch).}
Every optimal subarray ending at position $i$ either includes position $i-1$ (then extending the best subarray ending at $i-1$ is optimal) or it does not (then it must start at $i$). Kadane's recurrence enumerates exactly these two cases. The global maximum is the best over all endpoints.

\paragraph{Time and space.}
Kadane runs in $\mathcal{O}(m)$ time and $\mathcal{O}(1)$ extra space.

\subsection{From 1D to 2D: Row Compression with Kadane}

Any optimal rectangle $[i_1..i_2]\times[j_1..j_2]$ has some top row $i_1$ and bottom row $i_2$. For fixed $(i_1,i_2)$ we can \emph{compress} rows $i_1$ to $i_2$ into a single 1D array of column sums
\[
b_j = \sum_{i=i_1}^{i_2} A_{i,j}\quad (1 \le j \le n).
\]
Then the best horizontal span $[j_1..j_2]$ for these two rows is exactly the maximum subarray of $(b_1,\ldots,b_n)$, i.e.\ returned by Kadane1D. Enumerating all $i_1 \le i_2$ gives the global optimum.

\begin{algorithm}
\caption{MaxProfitRectangle2D$(A \in \mathbb{Z}^{n\times n})$ via row compression}
\begin{algorithmic}[1]
\State $\texttt{best} \gets -\infty$
\For{$\texttt{topRow} \gets 1$ \textbf{to} $n$}
  \State \textbf{for all } $\texttt{j}$: $\texttt{col}[\texttt{j}] \gets 0$ \Comment{start a new strip at \texttt{topRow}}
  \For{$\texttt{bottomRow} \gets \texttt{topRow}$ \textbf{to} $n$}
    \For{$\texttt{j} \gets 1$ \textbf{to} $n$}
      \State $\texttt{col}[\texttt{j}] \gets \texttt{col}[\texttt{j}] + A_{\texttt{bottomRow},\,\texttt{j}}$ \Comment{add the new row elements}
    \EndFor
    \State $\texttt{best} \gets \max\!\big(\texttt{best},\ \text{Kadane1D}(\texttt{col})\big)$
  \EndFor
\EndFor
\State \textbf{return} $\texttt{best}$
\end{algorithmic}
\end{algorithm}

\paragraph{Correctness (sketch).}
Fix any top/bottom rows $(i_1,i_2)$. For these rows, the sum of a rectangle equals the sum of its columns in the compressed array. Hence the best left/right boundary is exactly the maximum subarray. Taking the max over all $(i_1,i_2)$ covers the optimal rectangle.

\subsection{Time and Space Complexity}

The outer double loop enumerates $\mathcal{O}(n^2)$ row pairs, each Kadane call costs $\mathcal{O}(n)$ time, and the compression update per bottom row is also $\mathcal{O}(n)$. Therefore the total running time is
\[
\mathcal{O}(n^2) \cdot \mathcal{O}(n) \;=\; \mathcal{O}(n^3) .
\]

The space needed to exectute the algorithm is only $\mathcal{O}(n)$ for \texttt{col} (besides the input matrix).


\section{Sweet Tooth} \label{sec:SweetTooth}
\textsc{Ruben --}
Next we will turn to sweets distribution amongst children. In this exercise, we must split a stash of sweets among $c$ children so that everyone gets the same number of sweets. Each child has preferences per sweet type (smaller numbers mean ``more preferred''). We may eat the leftovers. The task is to find the smallest priority threshold $p$ such that a fair distribution exists where each child only receives sweets of priority at most $p$. % cf. sheet

\subsection{Problem Statement}

Let there be $t$ sweet types and a count vector $a \in \mathbb{N}^t$ with total $s=\sum_{k=1}^t a_k$. There are $c$ children and a preference matrix $P \in \{1,\dots,P_{\max}\}^{c \times t}$ with entries $P_{i,k}$ (lower is better). Each child must receive exactly
\[
\text{share} \;=\; \big\lfloor \tfrac{s}{c} \big\rfloor
\]
sweets; the remaining $s - c \cdot \text{share}$ pieces are ours.

For a threshold $p \in \{1,\dots,P_{\max}\}$, define decision variables $x_{i,k} \in \mathbb{N}$: number of sweets of type $k$ given to child $i$.

\[
\begin{aligned}
&\sum_{i=1}^c x_{i,k} \;\le\; a_k && \forall k=1,\dots,t \quad \text{(limited stock)} \\
&\sum_{k=1}^t x_{i,k} \;=\; \text{share} && \forall i=1,\dots,c \quad \text{(fair share)} \\
&x_{i,k} \;=\; 0 && \text{if } P_{i,k} > p \quad \text{(respect threshold)} \\
&x_{i,k} \in \mathbb{Z}_{\ge 0} && \text{(integrality).}
\end{aligned}
\]
We seek the minimum $p$ for which a feasible solution exists.
\vspace{0.3em}




\subsection{Flow Modeling}

Fix a threshold \(p\). We decide feasibility at this \(p\) by building a three-layer flow network
\[
s \;\longrightarrow\; \text{types }(T_1,\ldots,T_t) \;\longrightarrow\; \text{children }(C_1,\ldots,C_c) \;\longrightarrow\; t .
\]
The edges and capacities encode stock limits, the preference cutoff \(p\), and each child’s quota \(\textit{share}\):

\begin{itemize}
  \item \(s \to T_k\) has capacity \(a_k\): at most \(a_k\) items of type \(k\) can be allocated in total (stock).
  \item \(T_k \to C_i\) exists \emph{iff} \(P_{i,k} \le p\). For its capacity we can safely use
  \[
  \mathrm{cap}(T_k \!\to\! C_i) \;=\; \min\{a_k,\ \textit{share}\}.
  \]
This is the minimal safe capacity. Any larger value is also feasible, but redundant because the flow on $T_k\!\to\!C_i$ is already bounded by $s\!\to\!T_k$ (at most $a_k$) and by $C_i\!\to\!t$ (at most $\textit{share}$). Any smaller value can exclude feasible allocations when a child must receive (almost) all of its $\textit{share}$ from type $k$.
  \item \(C_i \to t\) has capacity \(\textit{share}\): this enforces that each child receives exactly \(\textit{share}\) sweets once the max flow hits the target value (see correctness).
\end{itemize}

We only insert edges \(T_k \!\to\! C_i\) that satisfy the preference cutoff \(P_{i,k} \le p\); disallowed pairs are absent from the network. With this construction, a feasible allocation at threshold \(p\) exists iff the maximum \(s\)-\(t\) flow equals \(c \cdot \textit{share}\).

After now having found a way to test whether there exists a feasible allocation for a fixed threshold \(p\), we search for the \emph{minimum} feasible threshold by binary search over
\[
p \in \{1,\ldots,P_{\max}\}, \qquad P_{\max} := \max_{i,k} P_{i,k}
\]
(which equals \(t\) if preferences are ranks \(1,\ldots,t\)).

\subsection{How We Compute the Max Flow}

Any max-flow/min-cut algorithm would decide feasibility at a fixed threshold \(p\) (e.g., \cite{EdmondsKarp72}, \cite{Dinitz70}, or Push–Relabel by \cite{GoldbergTarjan88}). We implement \emph{Dinitz’s algorithm} because it fits layered networks well and is simple with adjacency lists.

\paragraph{Dinitz (three-step view).}
We work on the \emph{residual network} (forward edges with residual \(c_f>0\) and reverse edges that allow canceling flow).

\textbf{Step 1 (BFS / level graph).} Run a BFS from \(s\) to label levels \(\ell(\cdot)\) using only residual edges. Keep only \emph{forward} residual edges with \(\ell(v)=\ell(u)+1\); this acyclic subgraph is the \emph{level graph}.

\textbf{Step 2 (early stop).} If \(t\) was not reached during BFS, there is no augmenting path; return the current flow as \emph{maximum}.

\textbf{Step 3 (DFS / blocking flow).} Using only edges of the level graph, do multiple DFS from \(s\) to \(t\). Each DFS finds a level-respecting augmenting path; push the path’s bottleneck value and update residuals. Maintain a \emph{current-arc} per node to skip exhausted edges. Stop when a \emph{blocking flow} is reached (no more \(s\)-\(t\) paths in the level graph).

Repeat Steps 1–3 until Step 2 triggers. With integer capacities, Dinitz returns an \emph{integral} max flow, which we directly read as integer assignments \(x_{i,k}\) on the \(T_k\!\to C_i\) edges.

\emph{Complexity.} The standard worst-case bound is \(O(EV^2)\) per feasibility check (here \(V=2+t+c\), \(E\le t+c+ct\)). Our network is shallow (paths have three naturally arising levels), so it's expected to perform well in practice.



\subsection{Correctness}

\begin{theorem}
For any threshold $p$, there exists a feasible allocation $\{x_{i,k}\}$ that satisfies stock, quota, and threshold constraints if and only if the maximum flow equals $c \cdot \text{share}$ in the network defined above.
\end{theorem}

\begin{proof}[Proof sketch]
($\Rightarrow$) Given a feasible $\{x_{i,k}\}$, send $x_{i,k}$ units along source$\to$type $k \to$child $i\to$sink. All capacities are respected by construction; the total flow is $\sum_i \text{share} = c \cdot \text{share}$.

($\Leftarrow$) From a max flow of value $c \cdot \text{share}$, read off $x_{i,k}$ from the flow on edges type $k \to$ child $i$. Capacities ensure $\sum_i x_{i,k} \le a_k$ and $\sum_k x_{i,k} \le \text{share}$; the child$\to$sink edge saturating to $\text{share}$ forces equality. Missing edges enforce $x_{i,k}=0$ when $P_{i,k} > p$.
\end{proof}

\subsection{Time and Space Complexity}

\textbf{Time.} Let $V = 2 + t + c$ and $E \le t + c + ct$ (source$\to$t types, up to $ct$ type$\to$child edges, $c$ child$\to$sink edges). One max-flow check with Dinitz runs in worst-case 
\[
\mathcal{O}(E \, V^2) \;=\; \mathcal{O}\big((ct)\,(c{+}t)^2\big).
\]
Binary search over \(p \in \{1,\ldots,P_{\max}\}\) adds a \(\log P_{\max}\) factor:
\[
\mathcal{O}\!\left(\log P_{\max}\cdot (ct)\,(c{+}t)^2\right).
\]
\textbf{Space.} Storing the residual network and Dinitz’s working arrays uses
$\mathcal{O}(V+E)=\mathcal{O}(ct+c+t)=\mathcal{O}(ct)$ space per feasibility check.
